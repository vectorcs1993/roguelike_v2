# Система очереди ходов (Fallout-style)

## Обзор

Реализована система очереди ходов по инициативе, аналогичная системе в игре Fallout. Система управляет очередностью ходов персонажей и врагов на основе значений инициативы.

## Основные компоненты

### 1. Класс TurnQueue (`src/game/TurnQueue.js`)

Основной класс, управляющий очередью ходов:

#### Ключевые особенности:
- **Инициатива**: Каждый персонаж имеет значение инициативы (от 1 до 10+)
- **Сортировка**: Очередь сортируется по убыванию инициативы
- **Режимы**: 
  - **Мирный режим**: Только персонажи игрока в очереди
  - **Боевой режим**: Персонажи игрока + враги в очереди
- **Раунды**: После прохождения всей очереди начинается новый раунд

#### Основные методы:
- `initialize(playerCharacters)` - инициализация очереди персонажами игрока
- `addCharacter(character, isEnemy)` - добавление персонажа/врага в очередь
- `next()` - переход к следующему ходу
- `spendInitiative(character, cost)` - уменьшение инициативы после действия
- `getCurrentCharacter()` - получение текущего активного персонажа

## Логика работы

### 1. Инициализация
При создании локации:
1. Создаются все персонажи (игроки и враги)
2. Вызывается `initializeTurnQueue()` 
3. В очередь добавляются только персонажи игрока
4. Очередь сортируется по инициативе

### 2. Мирный режим
- В очереди только персонажи игрока
- Ходы переходят автоматически при истощении AP
- Порядок определяется инициативой

### 3. Переход в боевой режим
Когда враг обнаруживает игрока:
1. AI врага переходит в состояние `COMBAT`
2. `updateEnemiesInTurnQueue()` добавляет врага в очередь
3. Система автоматически переключается в боевой режим
4. Враг добавляется в очередь согласно своей инициативе

### 4. Боевой режим
- В очереди перемешаны персонажи игрока и враги
- Порядок определяется инициативой
- После гибели врага он удаляется из очереди
- Если все враги уничтожены, система возвращается в мирный режим

### 5. Переход ходов
1. Текущий персонаж тратит AP на действия
2. Когда AP достигает 0, `shouldAdvanceTurn()` возвращает `true`
3. `nextTurn()` переходит к следующему персонажу в очереди
4. Новому персонажу восстанавливаются полные AP
5. Если очередь прошла полный круг, начинается новый раунд

## Тестирование

### Сценарии тестирования:

1. **Инициализация очереди**
   - Проверить, что очередь создается с персонажами игрока
   - Проверить сортировку по инициативе

2. **Автоматический переход ходов**
   - Израсходовать AP текущего персонажа
   - Убедиться, что ход автоматически переходит к следующему

3. **Добавление врагов в очередь**
   - Подвести персонажа к врагу
   - Убедиться, что враг добавляется в очередь при обнаружении

4. **Смешанная очередь**
   - Проверить, что в боевом режиме очередь содержит и игроков, и врагов
   - Проверить правильность порядка по инициативе

5. **Выход из боевого режима**
   - Уничтожить всех врагов
   - Убедиться, что система возвращается в мирный режим

## Известные ограничения

1. **Инициатива не восстанавливается полностью каждый раунд**
   - В текущей реализации инициатива сбрасывается к оригинальным значениям
   - В будущем можно добавить систему восстановления инициативы

2. **Нет ручного управления очередью**
   - В текущей реализации очередь управляется автоматически
   - В будущем можно добавить возможность ручного выбора следующего персонажа

3. **Нет визуального отображения очереди**
   - В будущем можно добачить UI-элемент для отображения порядка ходов
